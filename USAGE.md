# Использование support-ai-mcp

Инструкция для специалистов техподдержки, которые работают с заявками через ассистента с подключённым `support-ai-mcp`. Установка сервера описана в [README.md](README.md).

## Что делают два инструмента

Инструменты ищут в разных источниках, и разница между ними существенная.

**`search_tips`** — внутренние подсказки техподдержки. Возвращает **полный текст** подсказки, поэтому ассистент может сразу использовать её содержимое в ответе. Это основной источник, когда нужно решить проблему клиента.

**`search_articles`** — статьи Базы знаний на 5systems.ru. Возвращает только **заголовок и ссылку**, без текста статьи. Ассистент не видит, что внутри статьи, — он видит лишь то, что она релевантна запросу.

Практический вывод: содержимое ответа клиенту берётся из подсказок, а статьи прикладываются как ссылки «подробнее». Если нужно, чтобы ассистент опирался на содержание конкретной статьи, откройте её по ссылке и попросите разобрать текст — сам по себе он его не получит.

## Как формулировать запрос

Поиск семантический: работает по смыслу, а не по точному совпадению слов. Отсюда несколько правил.

**Ищите проблему, а не заявку целиком.** Копировать в поиск всё обращение клиента бесполезно — длинный текст с реквизитами, приветствием и десятью вопросами размывает смысл, и в ответ придёт случайное. Разложите обращение на отдельные вопросы и задайте их по одному.

**Формулируйте фразой, а не одним словом.** «Не печатается чек» найдёт больше, чем «чек». Одиночный термин слишком многозначен.

**Пробуйте язык программы, а не язык клиента.** Клиент пишет «не могу выставить счёт», в системе это может называться «реализация» или «заказ-наряд». Если по формулировке клиента ничего не нашлось, повторите поиск терминами интерфейса.

**Не бойтесь переформулировать.** Два-три разных захода по одному вопросу — нормальная практика, каждый запрос дёшев.

## Как читать результат

Возвращается **не более 5** результатов, отсортированных по релевантности. Первый — наиболее подходящий по мнению поиска, но это не гарантия: проверяйте, что найденное действительно про вопрос клиента.

**Пустой результат — это штатный ответ, а не сбой.** Он означает ровно одно: по такой формулировке ничего не нашлось. Переформулируйте запрос. Если после нескольких попыток пусто — скорее всего, темы в базе действительно нет, и заявку нужно эскалировать. Реальная ошибка выглядит иначе: ассистент сообщит про `HTTP error` или `unable to fetch` (см. раздел «Диагностика» в [README.md](README.md)).

**Релевантность ≠ правильность.** Поиск возвращает похожее по смыслу, а не проверенное решение. Найденная подсказка может относиться к другой версии релиза или к другому сценарию. Ответственность за применимость — на специалисте, который отправляет ответ.

## Как использовать в ответе клиенту

Разумный порядок работы с заявкой:

1. Выделить из обращения конкретные вопросы.
2. По каждому — `search_tips`, при необходимости с переформулировкой.
3. Отдельно `search_articles`, чтобы приложить ссылки на статьи.
4. Собрать ответ и **проверить его перед отправкой**: подсказка могла устареть, а статья — не покрывать частный случай клиента.

Не пересылайте клиенту текст подсказок дословно: подсказки внутренние и могут содержать служебные детали, не предназначенные для внешней переписки. Статьи Базы знаний, наоборот, публичны — ссылки на них давать можно и нужно.

## Чего сервер не делает

- **Не ищет по заявкам.** Похожие обращения из портала техподдержки недоступны — есть только подсказки и статьи.
- **Не отдаёт текст статей.** Только заголовок и ссылка.
- **Не имеет доступа к базе клиента.** Это поиск по документации, а не к данным 1С; за данными — API 5S AUTO.
- **Не фильтрует по версии релиза, продукту или дате.** Единственный параметр — текст запроса.
- **Не хранит контекст между запросами.** Каждый поиск независим, уточняющий запрос ищет заново.
